# Bug Report: Tool Call Detection Issues
**Date:** 2024-12-24
**Severity:** Medium (Token waste, UX degradation)
**Target Fix:** v1.11.4 (or later, after @git/@tree features)

## Summary
Both Perplexity and Gemini providers occasionally return raw JSON instead of executing tool calls, wasting tokens and requiring user intervention ("continue" command).

## Issues Discovered

### Issue #1: Raw JSON Response (Both Providers)
**Symptom:** LLM returns tool call as formatted JSON text instead of executing it

**Example (Perplexity):**
```
You: list the files in /tmp dir

A:
{
  "tool": "list_directory",
  "arguments": {
    "path": "/tmp",
    "format": "simple"
  }
}

You: continue
A: [tool executes on retry]
```

**Same issue occurs with Gemini provider.**

**Impact:**
- Wasted API tokens (double request needed)
- Poor UX (user must type "continue")
- Inconsistent behavior

**Root Cause:** Tool call detection regex in `perplexity_tools_prompt_based.py` doesn't catch all JSON formatting variations:
- Code blocks with markdown
- Inline JSON without markers
- Different whitespace/formatting

### Issue #2: Poor Tool Parameter Awareness
**Symptom:** LLM doesn't utilize available tool parameters, explains shell commands instead

**Example:**
```
You: use long list tool options

A: To get a long listing of files (detailed view) with ls, use the -l option:
   • ls -l
   • ls -la
   ...
```

**Expected:** Should have called `list_directory` with `format="long"` parameter.

**Impact:**
- Doesn't use tools when it should
- Wastes tokens explaining commands
- Confusing UX (tools enabled but not used)

**Root Cause:**
1. Tool descriptions don't emphasize parameters enough
2. System prompt doesn't strongly enforce tool usage over explanations
3. No few-shot examples showing parameter usage

## Blocker Assessment for @git/@tree Features

**Question:** Do these bugs block @git and @tree context provider implementation?

**Answer: NO - Not a blocker**

**Reasoning:**
- @git and @tree are **context injection features** (like @file)
- They add information to prompts, don't depend on tool execution
- Implementation doesn't require fixing tool call detection
- Similar to existing @file feature which works fine

**However:**
- Quality of @git/@tree features WILL be impacted if LLM can't reliably call tools
- Example: User provides git diff via @git, LLM should edit files using file editing tools
- If tool calls fail, the context is wasted

**Recommendation:** Implement @git/@tree first, THEN fix tool call reliability in v1.11.4+

## Proposed Fixes (for v1.11.4 or later)

### Fix #1: Robust Tool Call Detection
**Location:** `perplexity_tools_prompt_based.py:1054-1083`

**Current logic:**
```python
# Extracts JSON using first/last brace - too fragile
first_brace = text.find('{')
last_brace = text.rfind('}')
```

**Proposed improvements:**
1. Add markdown code block detection (```json, ```python, etc.)
2. Add regex for inline JSON with/without markers
3. Try multiple extraction strategies in order of confidence
4. Add debug logging when JSON detected but not executed
5. Add fallback: if response looks like JSON, try parsing aggressively

**Example improved logic:**
```python
def extract_tool_call_json(text: str) -> Optional[dict]:
    """Extract tool call JSON from LLM response - try multiple strategies."""

    # Strategy 1: Markdown code block
    if '```' in text:
        code_block = extract_from_code_block(text)
        if code_block and is_valid_tool_call(code_block):
            return code_block

    # Strategy 2: First/last brace (current approach)
    first_last = extract_first_last_brace(text)
    if first_last and is_valid_tool_call(first_last):
        return first_last

    # Strategy 3: Aggressive - assume entire response is JSON
    try:
        parsed = json.loads(text.strip())
        if is_valid_tool_call(parsed):
            logger.warning("Used aggressive JSON parsing - might indicate detection issue")
            return parsed
    except json.JSONDecodeError:
        pass

    return None
```

### Fix #2: Enhanced Tool Descriptions
**Location:** Tool registration in `perplexity_tools_prompt_based.py`

**Current:**
```python
"list_directory": "List files and directories in a path. Supports simple and long format (like 'ls -la')"
```

**Proposed:**
```python
"list_directory": {
    "description": "List files and directories in a path. Use this instead of explaining shell ls commands.",
    "parameters": {
        "path": "Directory to list (default: current directory)",
        "format": "Output format: 'simple' (filenames only) or 'long' (detailed like ls -la with permissions, size, dates)"
    },
    "examples": [
        {"request": "show files in /tmp", "call": {"path": "/tmp", "format": "simple"}},
        {"request": "detailed list of current dir", "call": {"path": ".", "format": "long"}}
    ]
}
```

### Fix #3: Stronger System Prompt
**Location:** Tool system prompt in `perplexity_tools_prompt_based.py`

**Add to system prompt:**
```
CRITICAL RULES FOR TOOL USAGE:

1. ALWAYS use available tools when user asks for information you can get via tools
2. NEVER explain how to use shell commands when a tool exists for that operation
3. If a tool has parameters (like format="long"), USE THEM - don't ignore them
4. Tool calls MUST be executed, not explained as examples

Examples:
❌ BAD: "To list files, use ls -la"
✅ GOOD: [calls list_directory with format="long"]

❌ BAD: "You can get weather with curl wttr.in"
✅ GOOD: [calls get_weather tool]
```

## UPDATE: v1.11.4 Bug Discovery - @git/@tree Context Injection

**Date:** 2024-12-24
**Severity:** Critical (BLOCKER for v1.11.4)
**Status:** ✅ FIXED

### Bug Description
During v1.11.4 development, discovered that @git and @tree context injection was NOT working in TUI:
- User typed: `Review @git and suggest improvements`
- TUI showed: `Including 1 file(s): .gitignore` ← WRONG!
- Expected: Git diff injected into message

### Root Cause
TUI was calling legacy `process_file_references()` BEFORE routing to EngineClient:
1. Line 261 in main.py: `augmented_input, resolved_files = handler.process_file_references(user_input)`
2. Legacy method fuzzy-matched "@git" to ".gitignore" file
3. Line 293: TUI passed `augmented_input` (modified) to EngineClient instead of `user_input`
4. EngineClient's ContextInjector received message with @git already stripped out
5. Context injection failed because @git reference was gone

### Fix Applied
**Files Changed:**
- `ppxai/main.py`: Skip `process_file_references()` when using EngineClient path
  - EngineClient path (line 270-303): Pass `user_input` directly
  - Legacy path (line 305-317): Use `process_file_references()` for backward compatibility
- `ppxai/common/event_handler.py`: Add CONTEXT_INJECTED event handling
  - Base EventHandler: Handle CONTEXT_INJECTED events
  - TUIEventHandler: Display injected contexts to user

**Verification:**
- All 31 context injection tests pass ✅
- Direct ContextInjector test passes ✅
  - @git injection: ✅ Works (5280 bytes injected)
  - @tree injection: ✅ Works (5286 bytes injected)
  - Combined @git + @tree: ✅ Works

### Impact
- **Before Fix:** @git/@tree completely broken in TUI (fuzzy-matched to wrong files)
- **After Fix:** @git/@tree work correctly through EngineClient's built-in context injection
- **Legacy Path:** Only supports @file (not @git/@tree) for backward compatibility
