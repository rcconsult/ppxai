    v1.15.0 Autocomplete and /show Implementation Analysis¶

    Date: 2026-01-27 Purpose: Analysis of Textual TUI autocomplete feature and /show command with python-magic integration Status: ✅ AUTOCOMPLETE IMPLEMENTED (updated v1.15.0)

    UPDATE (v1.15.0): The autocomplete issues documented below have been resolved by replacing the custom CompletionPopup with the textual-autocomplete library. See TEXTUAL-WIDGETS-RESEARCH.md and IMPLEMENTATION-PLAN-AUTOCOMPLETE-v1.16.0.md for details.

    Executive Summary¶

    This document analyzes two key features of the ppxaide (Textual TUI) implementation:

    1. Autocomplete System: ~~Fully implemented but DISABLED due to UI/UX issues~~ → ✅ NOW ENABLED using textual-autocomplete library
    2. File Type Detection: Working correctly with python-magic + extension fallback for intelligent /show command dispatching

    Key Findings: - ✅ Autocomplete logic is complete and functional (slash commands, @context providers, file paths) - ❌ Autocomplete UI has 5 critical issues preventing production use - ✅ python-magic integration works as designed with graceful fallback - ✅ Type-based rendering successfully dispatches to 5 specialized viewers - ✅ All viewer widgets support toggle between rendered/source views

    1.4 Why Autocomplete is Disabled¶

    Location: ppxai/tui/widgets/input_box.py:81-96

    Critical TODO comment: 

    # TODO: Autocomplete disabled - Phase 4/5 refactoring needed
# Current implementation issues:
# - Fixed offset positioning (offset-y: 90%) instead of cursor-based
# - Single column layout instead of multi-column like Rich TUI
# - No alphabetical sorting of file list
# - No lazy loading/virtual scrolling for large file lists
# - Fixed 100 file limit with no dynamic pagination
# Rich TUI uses prompt_toolkit with:
# - Cursor-based positioning (popup appears at '@' character)
# - Multi-column scrollable layout
# - Alphabetical sorting
# - Dynamic lazy loading as user scrolls
# See: ppxai/rich/completer.py for reference implementation

    1.5 Detailed Issue Analysis¶

    Issue #1: Fixed Offset Positioning¶

    Problem: offset-y: 90% positions popup at 90% of screen height, not at cursor Expected: Popup should appear directly below the '@' or '/' character being typed Rich TUI behavior: Uses prompt_toolkit.completion.Completer with cursor-aware positioning

    Issue #2: Single Column Layout¶

    Problem: All completions in a vertical list, limited to ~20 visible items Expected: Multi-column grid layout like Rich TUI (4-6 columns) Impact: Poor UX when showing 100 file paths

    Issue #3: No Alphabetical Sorting¶

    Problem: Files returned in os.walk() order (filesystem-dependent) Expected: Alphabetically sorted results for predictable navigation Rich TUI behavior: Sorts all completions before display

    Issue #4: No Lazy Loading¶

    Problem: Fixed 100 file limit with 5-second cache Expected: Virtual scrolling that loads files on-demand Impact: Large projects (1000+ files) have truncated results

    Issue #5: Fixed 100 File Limit¶

    Problem: Hardcoded MAX_FILES = 100 in completer.py:68 Expected: Dynamic pagination or infinite scroll Rich TUI behavior: No arbitrary limits, handles 10,000+ files

    1.6 Comparison: Rich TUI vs Textual TUI Autocomplete¶

    Feature Rich TUI (prompt_toolkit) Textual TUI (current)
    Cursor positioning ✅ At '@' character ❌ Fixed screen offset
    Layout ✅ Multi-column grid ❌ Single column
    Sorting ✅ Alphabetical ❌ Filesystem order
    Pagination ✅ Virtual scroll ❌ Fixed 100 limit
    File cache ✅ Smart invalidation ⚠️ 5-second expiry
    Keyboard nav ✅ Arrow keys ✅ Arrow keys
    Ignore patterns ✅ .git, node_modules ✅ .git, node_modules

    1.7 Recommendation¶

    Do NOT enable autocomplete in v1.15.0. The UI issues create a poor user experience that would reflect badly on the release. Instead:

    1. v1.16.0 (Phase 4): Refactor CompletionPopup to use Textual's OptionList with dynamic positioning
    2. v1.16.0 (Phase 4): Implement multi-column layout using GridLayout or custom widget
    3. v1.16.0 (Phase 4): Add alphabetical sorting and lazy loading
    4. v1.17.0 (Phase 5): Remove 100 file limit, implement virtual scrolling

    Existing workaround: Users can type file paths manually or use /cd to change working directory and reduce file count.

    Part 2: /show Command with python-magic¶

    2.1 Architecture¶

    The /show command uses a type-based renderer dispatch system:

    User: /show config.json
  ↓
File Type Detection (python-magic + extension fallback)
  ↓
Typed Result Object (TreeResult, TableResult, etc.)
  ↓
Renderer Dispatch (RichRenderer or TextualRenderer)
  ↓
Specialized Viewer Widget (DataViewer, TableViewer, etc.)

    2.2 File Type Detection Flow¶

    Location: ppxai/common/file_type.py:246-307

    Detection hierarchy: 

    def detect_file_type(path: Path, content: Optional[str] = None) -> FileType:
    # 1. Try libmagic (python-magic)
    try:
        import magic
        mime = magic.from_file(str(path), mime=True)
        if mime in MIME_TO_FILETYPE:
            return MIME_TO_FILETYPE[mime]
    except ImportError:
        pass  # Fallback to extension

    # 2. Fallback to extension mapping
    ext = path.suffix.lower()
    if ext in EXTENSION_TO_FILETYPE:
        return EXTENSION_TO_FILETYPE[ext]

    # 3. Check if binary (null bytes) or text
    if b'\x00' in chunk:
        return FileType.BINARY

    # 4. Unknown
    return FileType.UNKNOWN

    Supported file types:

    FileType Enum MIME Types Extensions Viewer Widget
    JSON application/json, text/json .json DataViewer (tree)
    YAML application/yaml, text/x-yaml .yaml, .yml DataViewer (tree)
    TOML application/toml .toml DataViewer (tree)
    HCL - .hcl, .tf DataViewer (tree)
    CSV text/csv .csv TableViewer
    TSV text/tab-separated-values .tsv TableViewer
    MARKDOWN text/markdown .md MarkdownResult (rendered)
    IMAGE image/* .png, .jpg, .gif, etc. ImageViewer
    CODE text/x-python, text/javascript, etc. .py, .js, etc. CodeEditor
    TEXT - .txt, .log CodeEditor (plain text)
    BINARY application/octet-stream - Error (not viewable)

    2.4 python-magic Integration¶

    Dependency: python-magic>=0.4.27 in pyproject.toml

    How it works: 

    import magic
mime = magic.from_file(str(path), mime=True)
# Returns: "application/json", "text/csv", "image/png", etc.

    Graceful fallback: 

    try:
    import magic
    mime = magic.from_file(str(path), mime=True)
except ImportError:
    # python-magic not installed, use extension fallback
    pass
except Exception:
    # Magic detection failed, use extension fallback
    pass

    Why this approach works: - Accuracy: libmagic inspects file contents, not just extensions (detects .json files saved as .txt) - Performance: Only reads first few KB of file for magic detection - Reliability: Extension fallback ensures it always works, even without python-magic - Cross-platform: Works on Linux (libmagic), macOS (libmagic), Windows (python-magic-bin)

    2.5 Viewer Widgets Implementation¶

    DataViewer (Tree + Source Toggle)¶

    Location: ppxai/tui/widgets/data_viewer.py:1-358

    Features: - Tree view: Hierarchical display with expand/collapse - Source view: Syntax-highlighted code editor - Ctrl+V toggle: Switch between views - Format support: JSON, YAML, TOML (with parser libraries) - Keybindings: e (expand all), c (collapse all)

    Rendering: 

    def _dict_to_tree(data: Any, label: str = "root") -> Dict[str, Any]:
    if isinstance(data, dict):
        return {"label": label, "children": [_dict_to_tree(v, k) for k, v in data.items()]}
    elif isinstance(data, list):
        return {"label": f"{label} ({len(data)} items)", "children": [...]}
    else:
        return {"label": f"{label}: {str(data)[:50]}", "children": []}

    TableViewer (Table + Source Toggle)¶

    Location: ppxai/tui/widgets/table_viewer.py:1-469

    Features: - Table view: Textual's DataTable with grid display - Source view: Raw CSV/TSV in code editor - Ctrl+V toggle: Switch between views - Delimiter detection: Auto-detects ,, \t, |, ; - Header detection: Heuristic to identify header rows - Performance: Limits to 1000 rows initially, max 50 char column width

    Delimiter detection: 

    def detect_delimiter(content: str) -> str:
    lines = content.split("\n")[:10]  # First 10 lines
    counts = {",": lines.count(","), "\t": lines.count("\t"), ...}
    return max(counts.items(), key=lambda x: x[1])[0]

    ImageViewer (Terminal Images with Fallback)¶

    Location: ppxai/tui/widgets/image_viewer.py:1-272

    Features: - Full mode: Uses textual-image>=0.8.0 for terminal image protocols (iTerm2, Kitty) - Fallback mode: Shows file info (dimensions, size, format) if library missing or terminal doesn't support images - Factory pattern: ImageHandlerFactory dispatches to FullImageHandler or FallbackHandler - Auto-scaling: Images scale to fit container width

    Factory dispatch: 

    class ImageHandlerFactory:
    @staticmethod
    def create(path: Path, viewer: "ImageViewer") -> ImageHandler:
        if is_full_mode_available():
            return FullImageHandler(path, viewer)
        else:
            return FallbackHandler(path, viewer)

    2.6 Type-Based Rendering Flow¶

    Example: /show data.json

    1. User types: /show data.json
   ↓
2. handle_show() in display.py
   - Resolves path: /path/to/data.json
   - Detects type: FileType.JSON (via python-magic or .json extension)
   ↓
3. Returns TreeResult(root={...}, metadata={content, language})
   ↓
4. TextualRenderer.render_tree_result()
   - Creates DataViewer widget
   - Parses JSON to dict
   - Converts dict to tree structure
   ↓
5. DataViewer displays:
   - Header: "data.json (tree) [Ctrl+V: source]"
   - TreeViewer with expand/collapse
   - User presses Ctrl+V → switches to CodeEditor with JSON syntax highlighting

    2.7 Toggle Feature (Rendered ↔ Source)¶

    All viewers support toggling:

    Viewer Rendered View Source View Toggle Key
    DataViewer Tree (hierarchical) Code (JSON/YAML/TOML) Ctrl+V
    TableViewer DataTable (grid) Code (CSV/TSV raw) Ctrl+V
    ImageViewer Terminal image N/A (images are binary) -
    MarkdownResult Rich markdown Code (markdown source) (handled by renderer)

    Metadata preservation: 

    # Original content stored for toggle
metadata={
    "content": content,      # Raw text for source view
    "language": "json",      # Syntax highlighting language
    "filepath": str(path)    # For display
}

    Toggle implementation in DataViewer: 

    def action_toggle_view(self) -> None:
    """Toggle between tree and source view (Ctrl+V)."""
    self.view_mode = "source" if self.view_mode == "tree" else "tree"

def watch_view_mode(self, mode: ViewMode) -> None:
    """React to view mode changes."""
    switcher = self.query_one("#data-content-switcher", ContentSwitcher)
    switcher.current = "tree-view" if mode == "tree" else "source-view"
    self._update_header()
    self._focus_current_view()

    Part 4: Conclusions¶

    4.1 Autocomplete Status¶

    Summary: Implementation is complete but disabled due to UI/UX issues.

    Do NOT enable in v1.15.0: - ❌ Fixed positioning creates confusing popup placement - ❌ Single column layout is poor UX for file lists - ❌ Unsorted results make navigation unpredictable - ❌ 100 file limit is too restrictive for large projects

    Recommended timeline: - v1.16.0 (Q2 2026): Refactor popup positioning + multi-column layout - v1.17.0 (Q3 2026): Virtual scrolling + remove file limit

    Workaround for v1.15.0 users: - Type file paths manually - Use /cd to navigate to subdirectories (reduces file count) - Use Rich TUI (ppxai) if autocomplete is critical

    4.2 /show Command Status¶

    Summary: Working correctly as designed.

    Strengths: - ✅ python-magic integration provides accurate file type detection - ✅ Extension fallback ensures it always works - ✅ Type-based dispatch is clean and extensible - ✅ All viewers support rendered ↔ source toggle - ✅ Graceful degradation (ImageViewer fallback, missing parser libraries)

    Ready for production: No issues found.

    4.3 Release Recommendation¶

    For v1.15.0: - ✅ Ship /show command as-is (working correctly) - ✅ Ship viewer widgets (DataViewer, TableViewer, ImageViewer, CodeEditor) - ❌ Keep autocomplete disabled (document in release notes)

    ### Known Limitations
