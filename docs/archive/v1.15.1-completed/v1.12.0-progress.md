## 💡 Design Decisions

### Why Hybrid Approach?

- **80% of dev projects**: Have git → Use git backend for atomic commits
- **20% without git**: Use file snapshots → Still get undo functionality
- **User experience**: Seamless, no configuration required (auto-detects)

### Why Git Commits Instead of Stash?

- **Stash issues**: Can be lost, confusing for users, fragile
- **Commit benefits**: Permanent history, `git log` visibility, `git revert` clarity
- **Prefix convention**: `ppxai checkpoint:` makes them easy to identify
- **Inspiration**: Aider uses this pattern successfully

### Why File Snapshots as Fallback?

- **Works anywhere**: Notebooks, scripts, non-git projects
- **Simple**: Just copy files to `~/.ppxai/checkpoints/`
- **Cleanup**: Auto-remove old checkpoints (keep last 10)
- **Transparent**: Users can inspect snapshots manually

## 🚀 User Value Proposition

**Before v1.12.0**: Agent mode can make destructive edits with no undo

**After v1.12.0**:
- ✅ Every agent task auto-checkpointed
- ✅ `/undo` restores all files atomically
- ✅ Safe experimentation with agent mode
- ✅ Works with or without git
- ✅ TUI and VSCode both supported
