### 1.5 Detailed Issue Analysis

#### Issue #1: Fixed Offset Positioning
**Problem:** `offset-y: 90%` positions popup at 90% of screen height, not at cursor
**Expected:** Popup should appear directly below the '@' or '/' character being typed
**Rich TUI behavior:** Uses `prompt_toolkit.completion.Completer` with cursor-aware positioning

#### Issue #2: Single Column Layout
**Problem:** All completions in a vertical list, limited to ~20 visible items
**Expected:** Multi-column grid layout like Rich TUI (4-6 columns)
**Impact:** Poor UX when showing 100 file paths

#### Issue #3: No Alphabetical Sorting
**Problem:** Files returned in `os.walk()` order (filesystem-dependent)
**Expected:** Alphabetically sorted results for predictable navigation
**Rich TUI behavior:** Sorts all completions before display

#### Issue #4: No Lazy Loading
**Problem:** Fixed 100 file limit with 5-second cache
**Expected:** Virtual scrolling that loads files on-demand
**Impact:** Large projects (1000+ files) have truncated results

#### Issue #5: Fixed 100 File Limit
**Problem:** Hardcoded `MAX_FILES = 100` in completer.py:68
**Expected:** Dynamic pagination or infinite scroll
**Rich TUI behavior:** No arbitrary limits, handles 10,000+ files

### 1.6 Comparison: Rich TUI vs Textual TUI Autocomplete

| Feature | Rich TUI (prompt_toolkit) | Textual TUI (current) |
|---------|---------------------------|----------------------|
| **Cursor positioning** | ✅ At '@' character | ❌ Fixed screen offset |

### 1.7 Recommendation

**Do NOT enable autocomplete in v1.15.0.** The UI issues create a poor user experience that would reflect badly on the release. Instead:

## Part 2: /show Command with python-magic

### 2.1 Architecture

The `/show` command uses a **type-based renderer dispatch** system:

```
User: /show config.json
  ↓
File Type Detection (python-magic + extension fallback)
  ↓
Typed Result Object (TreeResult, TableResult, etc.)
  ↓
Renderer Dispatch (RichRenderer or TextualRenderer)
  ↓
Specialized Viewer Widget (DataViewer, TableViewer, etc.)
```

### 2.2 File Type Detection Flow

**Location:** [ppxai/common/file_type.py:246-307](../ppxai/common/file_type.py#L246-L307)

**Detection hierarchy:**
```python
def detect_file_type(path: Path, content: Optional[str] = None) -> FileType:
    # 1. Try libmagic (python-magic)
    try:
        import magic
        mime = magic.from_file(str(path), mime=True)
        if mime in MIME_TO_FILETYPE:
            return MIME_TO_FILETYPE[mime]
    except ImportError:
        pass  # Fallback to extension

    # 2. Fallback to extension mapping
    ext = path.suffix.lower()
    if ext in EXTENSION_TO_FILETYPE:
        return EXTENSION_TO_FILETYPE[ext]

    # 3. Check if binary (null bytes) or text
    if b'\x00' in chunk:
        return FileType.BINARY

    # 4. Unknown
    return FileType.UNKNOWN
```

**Supported file types:**

| FileType Enum | MIME Types | Extensions | Viewer Widget |
|---------------|-----------|------------|---------------|
| `JSON` | `application/json`, `text/json` | `.json` | DataViewer (tree) |
| `YAML` | `application/yaml`, `text/x-yaml` | `.yaml`, `.yml` | DataViewer (tree) |
| `TOML` | `application/toml` | `.toml` | DataViewer (tree) |
| `HCL` | - | `.hcl`, `.tf` | DataViewer (tree) |
| `CSV` | `text/csv` | `.csv` | TableViewer |
| `TSV` | `text/tab-separated-values` | `.tsv` | TableViewer |
| `MARKDOWN` | `text/markdown` | `.md` | MarkdownResult (rendered) |
| `IMAGE` | `image/*` | `.png`, `.jpg`, `.gif`, etc. | ImageViewer |
| `CODE` | `text/x-python`, `text/javascript`, etc. | `.py`, `.js`, etc. | CodeEditor |
| `TEXT` | - | `.txt`, `.log` | CodeEditor (plain text) |
| `BINARY` | `application/octet-stream` | - | Error (not viewable) |

### 2.4 python-magic Integration

**Dependency:** `python-magic>=0.4.27` in `pyproject.toml`

**How it works:**
```python
import magic
mime = magic.from_file(str(path), mime=True)
# Returns: "application/json", "text/csv", "image/png", etc.
```

**Graceful fallback:**
```python
try:
    import magic
    mime = magic.from_file(str(path), mime=True)
except ImportError:
    # python-magic not installed, use extension fallback
    pass
except Exception:
    # Magic detection failed, use extension fallback
    pass
```

**Why this approach works:**
- **Accuracy:** libmagic inspects file contents, not just extensions (detects `.json` files saved as `.txt`)
- **Performance:** Only reads first few KB of file for magic detection
- **Reliability:** Extension fallback ensures it always works, even without python-magic
- **Cross-platform:** Works on Linux (libmagic), macOS (libmagic), Windows (python-magic-bin)

def _dict_to_tree(data: Any, label: str = "root") -> Dict[str, Any]:
    if isinstance(data, dict):
        return {"label": label, "children": [_dict_to_tree(v, k) for k, v in data.items()]}
    elif isinstance(data, list):
        return {"label": f"{label} ({len(data)} items)", "children": [...]}
    else:
        return {"label": f"{label}: {str(data)[:50]}", "children": []}
```

def detect_delimiter(content: str) -> str:
    lines = content.split("\n")[:10]  # First 10 lines
    counts = {",": lines.count(","), "\t": lines.count("\t"), ...}
    return max(counts.items(), key=lambda x: x[1])[0]
```

#### ImageViewer (Terminal Images with Fallback)

class ImageHandlerFactory:

### 2.6 Type-Based Rendering Flow

**Example: `/show data.json`**

```
1. User types: /show data.json
   ↓
2. handle_show() in display.py
   - Resolves path: /path/to/data.json
   - Detects type: FileType.JSON (via python-magic or .json extension)
   ↓
3. Returns TreeResult(root={...}, metadata={content, language})
   ↓
4. TextualRenderer.render_tree_result()
   - Creates DataViewer widget
   - Parses JSON to dict
   - Converts dict to tree structure
   ↓
5. DataViewer displays:
   - Header: "data.json (tree) [Ctrl+V: source]"
   - TreeViewer with expand/collapse
   - User presses Ctrl+V → switches to CodeEditor with JSON syntax highlighting
```

### 2.7 Toggle Feature (Rendered ↔ Source)

**All viewers support toggling:**

| Viewer | Rendered View | Source View | Toggle Key |
|--------|---------------|-------------|------------|
| **DataViewer** | Tree (hierarchical) | Code (JSON/YAML/TOML) | Ctrl+V |
| **TableViewer** | DataTable (grid) | Code (CSV/TSV raw) | Ctrl+V |
| **ImageViewer** | Terminal image | N/A (images are binary) | - |
| **MarkdownResult** | Rich markdown | Code (markdown source) | (handled by renderer) |

**Metadata preservation:**
```python
# Original content stored for toggle
metadata={
    "content": content,      # Raw text for source view
    "language": "json",      # Syntax highlighting language

}
```

**Toggle implementation in DataViewer:**
```python
def action_toggle_view(self) -> None:
    """Toggle between tree and source view (Ctrl+V)."""
    self.view_mode = "source" if self.view_mode == "tree" else "tree"

def watch_view_mode(self, mode: ViewMode) -> None:
    """React to view mode changes."""
    switcher = self.query_one("#data-content-switcher", ContentSwitcher)
    switcher.current = "tree-view" if mode == "tree" else "source-view"
    self._update_header()
    self._focus_current_view()
```
